### 功能概述

- 定时（默认 5 分钟）探测公网连通性，掉线时自动登录校园网门户 `10.9.1.3:801`
- 现代自绘 GUI（侧栏导航、深色/浅色主题、卡片布局）
- 系统托盘：最小化后驻留通知区，右键菜单可检测/登录/启停/退出
- 开机自启：界面开关控制，写当前用户注册表 `Run` 键，无需管理员权限
- 首次运行自动生成 `config.ini`

### 3.2 已知待改进（优先级：中）

1. **代码签名缺失**
   - 没有代码签名证书，Windows 智能控制（SAC）/ SmartScreen 仍可能拦截首次运行
   - v1.0.2 的缓解措施（`启动.cmd`、MOTW 自愈）仍在，但无法根除
   - 若用户愿意购买证书（个人开发者通常每年数千元），需要：
     - 在 `build_onedir.spec` 里加签名步骤，或用 `signtool` 对 exe 二次签名
     - 注意 PyInstaller 打包后签名要放在最后一步

2. **`build_onefile.spec` 未经完整验证**
   - 该配置存在但产物在本机沙箱无法启动（临时目录解压被拒）
   - 真实用户环境可能可用，但**未实测**
   - 若要用单文件模式，需先在真实环境验证

3. **托盘图标在高 DPI 下的显示**
   - 当前只加载了 `app.ico` 的默认尺寸
   - 高分屏下图标可能偏小或模糊，可考虑加载多尺寸

4. **开机自启在托盘模式下的交互**
   - 开机自启以 `--daemon` 启动，经 `app._is_cli()` 判定为 CLI 模式，**只跑守护进程、不开界面**
   - 因此**开机自启后没有托盘图标**，用户需手动双击 exe 才会看到界面与托盘
   - 若希望开机后也有托盘常驻，需要改造成"守护进程 + 托盘宿主"的形态
     （例如 daemon 模式下也加载 GUI 的托盘部分，但不显示主窗口）
   - 这是当前设计的一个已知取舍，**不是 bug**，但用户可能会困惑

## 四、接手方必须知道的关键背景

### 4.1 开发环境特殊限制（**最重要**）

本机（`D:\code\dsh\school_network`）运行在 **DeepSeek Harness 沙箱**中，存在以下限制：

| 限制 | 表现 | 影响 |
|---|---|---|
| **PyInstaller 不在全局环境** | `python -m PyInstaller` 直接报 `No module named PyInstaller` | 必须先设 `PYTHONPATH` |
| `Shell_NotifyIcon` 被拒 | 返回错误码 5 | 托盘图标无法真实验证 |
| `Start-Process` 偶发挂起 | 命令卡住不返回 | 测试要用 `subprocess.Popen` |
| `tasklist` 在沙箱中挂起 | 无法用它检测进程 | 改用 `Get-CimInstance Win32_Process` |
| `sh.exe` 无法创建管道 | git 凭据助手报错但不影响功能 | 可忽略 |
| 用户目录不可写 | 无法写 `%USERPROFILE%` | 配置只能放程序目录或项目内 |

**打包必须先执行**：

```powershell
$env:PYTHONPATH='D:\code\dsh\school_network\.build\pylib'
$env:TMP='D:\code\dsh\school_network\.build\tmp'
$env:TEMP='D:\code\dsh\school_network\.build\tmp'
python -m PyInstaller build_onedir.spec --noconfirm --distpath .build\onedir --workpath .build\work2
```

> PyInstaller 6.22.3 安装在 `.build/pylib`，是通过解压 wheel 手动放置的
> （pip 安装因沙箱临时目录权限失败）。`.build/` 已被 gitignore。

### 4.2 登录协议的关键细节

登录参数来自登录页 `a42.js` 的真实逻辑，不要随意改动：

```
GET http://10.9.1.3:801/eportal/?c=Portal&a=login
    ?login_method=1
    &user_account=,0,学号@cucc        ← 前缀 ",0," 是 PC 端固定值
    &user_password=密码
    &wlan_user_ip=本机IP              ← 必须是真实校园网 IP
    &wlan_user_mac=本机MAC
    &wlan_ac_ip=&wlan_ac_name=
    &jsVersion=3.3.3
```

**返回码含义**（`RET_CODE_MSG`，来自 `a42.js`）：

| ret_code | 含义 | 处理 |
|---|---|---|
| 1 | 账号或密码不对 | 会附上提交的 IP，便于判断是否网卡取错 |
| 2 | 终端 IP 已经在线 | **视为成功** |
| 3 / 4 | 系统繁忙 / 未知错误 | 指数退避重试 |
| 7 / 8 | Radius 认证失败 / 超时 | 重试 |
| 998 | Portal 协议参数不全 | 检查参数 |

### 4.3 IP 选取逻辑（曾导致严重误报）

`get_local_ip()` 的实现要点：

1. 先问系统「访问 `10.9.1.3:801` 用哪个源地址」
2. **过滤虚拟网卡**：`198.18.0.0/15`（Clash 等代理常用）、`169.254/16`、`192.0.2/24`、`127/8`
3. 仍不可信时枚举网卡，优先选 `10.x` 网段

> 这是 v1.0.1 的核心修复。**不要简化这段逻辑**，否则装了代理的用户会再次遇到"密码错误"。

### 4.5 敏感信息处置

| 位置 | 内容 | 处理 |
|---|---|---|
| `config.ini`（本地） | 真实学号 + 密码（不要写进任何提交物） | gitignored，**不要提交** |
| `.secrets/github_token.bin` | GitHub 令牌（DPAPI 加密） | gitignored |
| `_token.py` / `_askpass.py` / `_gh.py` | 令牌读写工具 | gitignored（`_*.py`） |

**历史事故**：2026-10-27 曾因 README 示例日志含真实内网 IP/MAC 而整仓删除重建。
重建后历史是干净的，但**每次提交前请扫描**：

```powershell
# 把真实值填进 NEEDLES 再运行；本文件不留真实值
python -c "
from pathlib import Path
NEEDLES = ['<学号>', '<内网IP前缀>', '<MAC>', 'ghp_']
skip={'.git','.build','dist','__pycache__','.secrets','logs'}
hits=[]
for p in Path('.').rglob('*'):
    if not p.is_file() or any(x in p.parts for x in skip): continue
    if p.name=='config.ini': continue
    try: t=p.read_text(encoding='utf-8',errors='ignore')
    except: continue
    for n in NEEDLES:
        if n and n in t: hits.append((str(p),n))
print('命中:', hits or '无')
"
```

> 注意：`_gh.py` / `_token.py` / `_askpass.py` 被 `_*.py` 规则忽略，
> 不会进入仓库，但它们**含有读取令牌的逻辑**，不要误改或误删。

### 4.6 Git 与发布流程

**推送**（本机 `github.com:443` 时通时不通，需特殊配置）：


> 若 `_askpass.py` 或 `_token.py` 丢失，凭据助手会失效（曾在清理文件时误删过一次）。
> 恢复方法：从 `.secrets/github_token.bin` 重新生成，或重新 `python _token.py save <新令牌>`。

**发布 Release**：

仓库内没有现成的发布脚本（`_release_*.py` 每次都是临时写的，用完即删）。
发布需要：

1. 用 `python _gh.py POST /repos/jijijitian/soochow-university-campus-net/releases '{...}'`
   创建 Release（`tag_name` / `target_commitish=main` / `prerelease: false`）

### 4.7 打包注意事项

1. **入口是 `app.py`**，不是 `gui.py`（`app.py` 负责分发 CLI/GUI）
2. **`build_onedir.spec` 的 `datas` 必须包含**：
   `assets/*`、`config.example.ini`、`auto_login.py`、`gui.py`、`motw.py`、`console.py`、`tray.py`
3. **`hiddenimports` 必须包含**：`auto_login`、`gui`、`motw`、`console`、`tray`

## 五、给接手方的建议顺序

1. **先确认环境**：跑 `python app.py --check`，确认源码模式可用

   这三个是最容易"看起来像新问题"的老问题，先查 CHANGELOG 确认
