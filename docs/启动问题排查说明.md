## 一、背景

用户开发了一个 Windows 桌面程序「校园网自动登录」（Python + tkinter，用 PyInstaller 打包），
发布在 GitHub：

```
仓库地址：https://github.com/jijijitian/soochow-university-campus-net
最新版本：v1.0.4
发布包  ：campus-autologin-v1.0.4-win64.zip
```

程序功能：定时检测公网连通性，掉线时自动登录苏州大学校园网门户（Dr.COM ePortal）。
界面支持配置账号密码、运营商、检测间隔，以及开机自启。

### 包结构（onedir 模式）

解压后长这样：

```
校园网自动登录\
├─ 校园网自动登录.exe          ← 主程序，约 2.1 MB
├─ 启动.cmd                    ← 备选启动器
├─ 使用说明.txt
├─ 被拦截怎么办.txt
├─ config.example.ini
└─ _internal\                  ← 约 997 个依赖文件，总 30 MB 左右
   ├─ python313.dll
   ├─ _tcl_data\
   ├─ _tk_data\
   └─ ...（大量 .pyd / .dll）
```

**关键：`_internal` 目录必须完整存在**，exe 单独拿出来无法运行。

## 二、当前问题

用户在这台电脑上**双击 `校园网自动登录.exe` 后打不开程序**：

- 表现为「双击后没有反应」或「窗口长时间不出、像卡死」
- 之前某个版本曾经出现过「窗口出现但长时间挂起，只能手动关掉」
- 同一份压缩包在开发者机器上可以正常启动（约 1 秒弹出窗口）

### 已经做过的修复（v1.0.1 → v1.0.4）

排查过程中已经修改过以下几点，请**不要重复怀疑**这些方向：

| 版本 | 已修复内容 |
|---|---|
| v1.0.1 | 登录 IP 取错（虚拟网卡 198.18.x.x 被当作校园网 IP） |
| v1.0.2 | 被 Windows 智能控制拦截（新增启动器、MOTW 自愈） |
| v1.0.3 | **启动卡死**：原来每次启动递归扫描近千文件的 MOTW 标记，在装了实时防护的机器上累计几十秒。已改为只处理 exe 自身 + 后台线程 |
| v1.0.4 | 去掉启动时的黑色控制台窗口（改为 GUI 子系统） |

也就是说：**递归扫描 MOTW 的性能问题、黑框问题、包不完整检测都已经处理过**。
现在的 v1.0.4 若仍打不开，需要实测数据来定位，不能靠猜。

## 三、你需要做的事

### 前置：确认材料

1. 确认用户手上的包是 **v1.0.4**（`campus-autologin-v1.0.4-win64.zip`）
2. 确认已**完整解压**（解压后应有 `_internal` 目录，里面近千个文件）
3. 建议先复制一份到桌面等**路径不含空格和中文的目录**再测试，
   例如 `C:\cn-test\`

> ⚠️ 如果用户手上还是旧版本，请先从上面的 GitHub Release 重新下载 v1.0.4 再继续。

### 第 1 步：检查文件完整性

在解压目录打开 PowerShell（**在文件夹空白处 Shift + 右键 → 在此处打开 PowerShell 窗口**），
执行：

```powershell
# 当前目录结构
Get-ChildItem | Select-Object Name, Length

# _internal 是否存在、有多少文件
Test-Path .\_internal
(Get-ChildItem .\_internal -Recurse -File | Measure-Object).Count

# 关键文件是否齐全
@(
  '_internal\python313.dll',
  '_internal\_tcl_data',
  '_internal\_tk_data'
) | ForEach-Object { "$_ : $(Test-Path $_)" }

# exe 的版本号
(Get-Item '.\校园网自动登录.exe').VersionInfo |
  Select-Object FileVersion, ProductVersion, FileDescription
```

**记录**：目录是否完整、文件数、三个关键路径是否存在、版本号是否为 `1.0.4`。

如果 `_internal` 缺失或文件数明显少于 900，说明**解压不完整或被杀毒软件隔离**，
请直接跳到第 6 步（检查杀毒软件），并让用户重新解压。

---

### 第 2 步：检查文件的「来自网络」标记

从网上下载的 zip 解压后，文件可能带 Zone.Identifier 标记，被 Windows 拦截。

```powershell
# 检查 exe 是否带 MOTW
Get-Item '.\校园网自动登录.exe' -Stream Zone.Identifier -ErrorAction SilentlyContinue |
  Select-Object Stream, Length

# 检查整个目录有多少文件带标记（只统计 exe 和 dll，避免太慢）
$marked = 0
Get-ChildItem . -Recurse -Include *.exe, *.dll -ErrorAction SilentlyContinue |
  ForEach-Object {
    if (Get-Item $_.FullName -Stream Zone.Identifier -ErrorAction SilentlyContinue) {
      $marked++
    }
  }
"带标记的文件数：$marked"
```

**记录**：exe 是否带标记、带标记的文件总数。

如果 exe 带标记，先解除再测：

```powershell
Unblock-File -Path '.\校园网自动登录.exe'
```

---

### 第 3 步：用命令行方式启动，抓取退出码

这一步骤最关键，请务必执行并把结果原样记录。

```powershell
cd <解压目录>

# 直接运行 exe，等待退出后打印退出码
$p = Start-Process -FilePath '.\校园网自动登录.exe' -PassThru
Start-Sleep -Seconds 8
if ($p.HasExited) {
    "进程已退出，退出码：$($p.ExitCode)  (0x{0:X8})" -f $p.ExitCode
} else {
    "进程仍在运行，PID：$($p.Id)"
    # 看它有没有窗口
    Get-Process -Id $p.Id | Select-Object Id, ProcessName, MainWindowTitle, Responding
}
```

**记录**：

- 退出码（十进制和十六进制都要）
- 如果进程还在跑，`MainWindowTitle` 是什么（空 = 没有窗口）
- `Responding` 是 True 还是 False（False = 卡死）

**退出码对照**（这些是 Python 解释器 PyInstaller 的常见退出码）：

| 退出码 | 十六进制 | 含义 |
|---|---|---|
| 0 | 0x0 | 正常退出 |
| 1 | 0x1 | 程序内部错误（会写 startup-error.log） |
| -1073741819 | 0xC0000005 | 内存访问冲突，通常是 DLL 冲突或 Tcl/Tk 问题 |
| -1073741515 | 0xC0000135 | 找不到依赖 DLL |
| -1073741701 | 0xC000007B | 32/64 位不匹配或 DLL 损坏 |
| -1 | 0xFFFFFFFF | bootloader 层失败（找不到 _internal 或 python dll） |

### 第 4 步：读取程序自己写的追踪日志

v1.0.4 会在**每次启动**时写 `startup-trace.log`，就在 exe 旁边。

```powershell
# 追踪日志（最重要）
if (Test-Path '.\startup-trace.log') {
    Get-Content '.\startup-trace.log' -Encoding UTF8 -Tail 40
} else {
    "startup-trace.log 不存在 —— 说明 Python 代码根本没有开始执行"
}

# 致命错误日志
if (Test-Path '.\startup-error.log') {
    Get-Content '.\startup-error.log' -Encoding UTF8
} else {
    "startup-error.log 不存在"
}

# 运行日志（界面起来过才会有）
if (Test-Path '.\logs\auto_login.log') {
    Get-Content '.\logs\auto_login.log' -Encoding UTF8 -Tail 20
} else {
    "logs\auto_login.log 不存在 —— 界面没有启动成功"
}
```

**判读方法**：

| 现象 | 结论 |
|---|---|
| `startup-trace.log` 完全不存在 | Python 代码没执行 → bootloader 层失败，问题在打包/依赖 |
| 有 trace 但停在「入口开始」之前 | 导入阶段失败 |
| 有 trace 且到「进入界面模式」 | Python 侧正常，问题在 tkinter 或窗口创建 |
| 有 `startup-error.log` | 按里面的中文说明处理（通常是文件不完整） |

### 第 5 步：运行内置诊断模式

v1.0.4 内置了 `--diag` 参数，会打印环境信息并生成 `diagnose.txt`。

```powershell
cd <解压目录>
.\校园网自动登录.exe --diag --quiet
Start-Sleep -Seconds 3
if (Test-Path '.\diagnose.txt') {
    Get-Content '.\diagnose.txt' -Encoding UTF8
} else {
    "diagnose.txt 未生成"
}
```

> 加 `--quiet` 不会弹对话框，适合脚本调用。
> 不加的话会弹一个窗口显示结果，点「确定」即可，同样会写 `diagnose.txt`。

**记录**：`diagnose.txt` 的完整内容。

### 第 6 步：检查杀毒软件 / 安全软件

这是「文件完整但打不开」的高频原因。

```powershell
# Windows Defender 隔离记录
Get-MpThreatDetection -ErrorAction SilentlyContinue |
  Select-Object -Last 10 |
  Format-List ThreatID, Resources, InitialDetectionTime, ActionSuccess

# 受控文件夹访问（勒索软件防护）是否开启
(Get-MpPreference).EnableControlledFolderAccess

# 已安装的第三方安全软件
Get-CimInstance -Namespace root\SecurityCenter2 -ClassName AntiVirusProduct -ErrorAction SilentlyContinue |
  Select-Object displayName, productState
```

同时请用户**手动检查**：

- Windows 安全中心 → 病毒和威胁防护 → 保护历史记录，看有没有隔离本程序的记录
- 如果有第三方安全软件（360、火绒、联想管家等），检查其隔离区

**记录**：Defender 是否有拦截记录、第三方安全软件名称、受控文件夹访问是否开启。

---

### 第 7 步：检查 Windows 智能控制 / SmartScreen

Windows 11 的「智能控制」会拦截未签名程序。

```powershell
# 智能控制状态（0=关闭, 1=强制, 2=评估）
(Get-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy' -ErrorAction SilentlyContinue).VerifiedAndReputablePolicyState

# SmartScreen 状态
(Get-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer' -ErrorAction SilentlyContinue).SmartScreenEnabled

# 系统版本（智能控制只在 Win11 较新版本上有）
[System.Environment]::OSVersion.Version
(Get-CimInstance Win32_OperatingSystem).Caption
```

**记录**：上面三个值。

---

### 第 8 步：用备选启动器测试

```powershell
cd <解压目录>
.\启动.cmd
Start-Sleep -Seconds 8

# 看进程是否起来（按 exe 路径匹配，避免中文进程名匹配问题）
Get-CimInstance Win32_Process |
  Where-Object { $_.ExecutablePath -like '*校园网自动登录.exe' } |
  Select-Object ProcessId, ExecutablePath
```

`启动.cmd` 会先做完整性检查：

- 如果它打印「程序文件不完整」→ 说明确实缺文件，按提示重新解压
- 如果它打印「正在启动」但进程没起来 → 说明是启动环节被拦截

**记录**：启动器的输出、进程是否存在。

## 五、几个重要提示

1. **不要跳过第 3 步和第 4 步**。退出码 + trace 日志是定位问题最直接的信息。

2. **不要假设是"文件不完整"**。v1.0.4 已经内置了完整性检查，如果真的缺文件，
   程序会弹出一个明确的中文对话框说明缺什么。如果用户看到的是"完全没反应"，
   那更可能是 bootloader 层就失败了，需要第 3 步的退出码来判断。

3. **中文路径可能是个因素但概率不高**。如果解压路径里有中文或空格，
   建议复制到 `C:\cn-test\` 再测，这是排除变量最简单的方法。

4. **注意区分「窗口没出现」和「窗口出现但卡住」**。前者是启动失败，
   后者是界面初始化或事件循环问题，两者的排查方向完全不同。
   请在第 3 步中明确记录 `MainWindowTitle` 和 `Responding`。

5. **如果 trace 日志显示走到了「进入界面模式」**，说明 Python 侧完全正常，
   问题在 tkinter 创建窗口或 Tcl/Tk 库加载。这时请检查：
   - `_internal\_tcl_data\init.tcl` 是否存在
   - 系统是否装了某些会 hook 窗口创建的软件（输入法、屏幕录制、远程控制）

6. **报告里不要包含用户的账号密码**。`config.ini` 里有明文密码，
   如果用户提供了这个文件，请把 `password =` 后面的内容抹掉再交回。
